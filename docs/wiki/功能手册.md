# 功能手册

左侧导航共八项：总览、容器、镜像、编排、应用商店、AI 助手、文件管理、日志记录。本页逐项说明。

---

## 总览

![总览](https://raw.githubusercontent.com/myyyisbest/wpanel/main/docs/screenshots/overview-light.png)

**顶部总控条**（按当前状态动态出现）：

| 按钮 | 出现条件 | 行为 |
|---|---|---|
| 启动 Ubuntu | 发行版未运行 | 拉起发行版并 `systemctl start docker.service` |
| 管理容器 | Ubuntu + Docker 均在运行 | 跳到「容器」页 |
| 停止 Docker | Ubuntu + Docker 均在运行 | 停止 Docker 相关单元（**WSL 保持运行**），需确认 |
| 安全关闭 WSL | 发行版运行中 | 先 `docker stop` 全部容器，再停止 Docker 与已配置的服务，最后 `wsl --terminate`，需确认 |

**八张卡片**：

1. **Ubuntu WSL2** —— 运行状态、systemd 是否启用、发行版 IP、运行时长；
2. **Docker Engine** —— 版本号、运行中 / 总容器数；
3. **WSL 内存** —— 已用 / 总量，附最近 5 分钟趋势；
4. **WSL CPU** —— 实时占用率与 5 分钟趋势（每 5 秒采样一次）；
5. **关键服务** —— Docker 与你在 `data/wpanel.local.json` 中配置的服务，可逐个启停；
6. **WSL 磁盘** —— 根分区已用 / 总量、使用率条、运行时长；
7. **Docker 占用** —— 镜像 / 容器 / 卷 / 构建缓存的数量与体积；
8. **最近操作** —— 审计日志的最新几条，点「全部 →」跳日志页。

> 顶部「每 5 秒刷新」可关闭自动刷新，右侧 ↻ 手动刷新，☀/🌙 切换主题。

## 容器

![容器卡片视图](https://raw.githubusercontent.com/myyyisbest/wpanel/main/docs/screenshots/containers-cards-light.png)

- **双视图**：卡片（默认，信息密度低、适合少量容器）与列表（适合大量容器）。右上角分段控件切换。
- **搜索**：按容器名过滤。
- **分组**：带 `com.docker.compose.project` 标签的容器会显示所属 Compose 项目，卡片上方标注 `blog`、`halo` 等；没有标签的显示「独立容器」。
- **操作**：
  - 运行中 → 停止 / 重启 / 日志 / 命令 / 详情
  - 已停止 → 启动 / 日志 / 删除
- **端口徽章**：`:3306`、`:8090` 等点击直达 `http://localhost:<端口>`。
- **清理已停止**：一键 `docker container prune -f`，仅当存在已停止容器时出现。

### 容器详情

点容器名或「详情」打开侧栏，展示镜像、状态、启动时间、重启次数、重启策略、端口映射、挂载、网络、环境变量（截断到 40 条）。`Esc` 关闭。

### 容器命令盒（实验性）

在运行中的容器里执行**单条**命令（`docker exec <name> sh -c "<命令>"`），输出限制 64KB，不支持换行。见[安全模型](安全模型)中的边界说明。

## 实时日志

![容器日志](https://raw.githubusercontent.com/myyyisbest/wpanel/main/docs/screenshots/container-logs-light.png)

- 走 SSE 流式推送 `docker logs -f`，不是轮询；
- 行数可在 **100 / 250 / 1000** 之间切换，切换即重连；
- 「跟随」开关控制是否实时滚动到底部；「复制」把当前缓冲全文写入剪贴板；「↻」重新拉取；
- 关闭弹窗或断开连接时，后端会立即 `kill` 掉对应的 `docker logs` 子进程；
- 每 15 秒发送一次 `: ping` 心跳，避免中间层掐断长连接。

Compose 项目也有独立的日志入口（`docker compose logs --tail <n>`，一次性拉取）。

## 镜像与卷

![镜像与卷](https://raw.githubusercontent.com/myyyisbest/wpanel/main/docs/screenshots/images-volumes-light.png)

### 镜像

| 操作 | 说明 |
|---|---|
| 拉取镜像 | 手动输入镜像名；**自动套用商店的镜像加速站设置**，后台任务流式输出日志 |
| 导入 | 上传 `docker save` 生成的 tar，上限 2GB |
| 导出 | 流式下载 `docker save` 的 tar，文件名优先使用 `仓库_标签.tar` |
| 清理悬空 | `docker image prune -f` |
| 清理未使用 | `docker image prune -a -f`（会删掉所有未被容器引用的镜像） |
| 删除 | 按镜像 ID 删除单条 |

### 卷

| 操作 | 说明 |
|---|---|
| 列表 | 名称、驱动、被引用数、占用大小（解析 `docker system df -v`） |
| 清理未使用 | `docker volume prune -a -f` |
| 删除 | 按名称删除单个卷 |

> 删除与清理都需要前端确认，并写入审计日志。

## Compose 编排

![Compose 编排](https://raw.githubusercontent.com/myyyisbest/wpanel/main/docs/screenshots/compose-light.png)

- **扫描目录**：默认发行版默认用户的 `~/compose`，可用 `WPANEL_COMPOSE_DIR` 覆盖。页面标题下方会显示实际扫描路径。
- **自动发现**：目录下每个子目录中若存在 `compose.yaml` / `compose.yml` / `docker-compose.yaml` / `docker-compose.yml` 之一，即识别为一个项目。
- **状态**：按容器标签实时汇总 `运行中 / 总数`；从未部署的显示「未部署」。
- **操作**：
  - **启动** —— `docker compose up -d`
  - **停止** —— `docker compose down`，可选「同时删除卷」（`down -v`）
  - **编辑** —— 直接在面板里改 compose 文件并保存
  - **日志** —— `docker compose logs --tail 250`
  - **删除** —— 先 `down`（失败则忽略），再删除整个项目文件夹，**双重确认**；默认保留数据卷
- **新建项目** —— 在扫描目录下创建新项目（目录 + compose 文件）。

> 目录与项目名以位置参数传给 `bash`，不做字符串拼接，因此项目名中的特殊字符不会造成命令注入。

## 应用商店

![应用商店](https://raw.githubusercontent.com/myyyisbest/wpanel/main/docs/screenshots/store-light.png)

- **默认模板源**：[1Panel 官方商店](https://github.com/1Panel-dev/appstore)（`main` 分支），通过 codeload tarball 下载并解压到本地缓存 `data/store-cache/`。
- **模板兼容**：兼容 1Panel 的 `data.yml` 结构，读取应用名、简介、标签、官网、仓库、文档、版本目录、`formFields` 表单定义与 `docker-compose.yml`。**模板中的脚本类字段一律忽略**。
- **镜像加速站**：默认 `docker.1ms.run`，安装时自动改写 compose 中的 `docker.io` 镜像地址；其他 registry（`ghcr.io`、`quay.io`、私有仓库）保持原样。留空即直连。
- **自定义源**：界面「商店设置」里可改仓库、分支与加速站，持久化到 `data/wpanel.local.json` 的 `store` 段。改动仓库 / 分支会清空本地缓存并重新下载。

### 安装流程

![安装预览](https://raw.githubusercontent.com/myyyisbest/wpanel/main/docs/screenshots/store-install-light.png)

1. 点应用卡片「安装」→ 后端读取该应用的最新版本元数据与表单字段；
2. 填写参数（端口、密码、数据目录等），**参数校验规则**：`paramPort` 必须是 1–5 位数字；`type: number` 必须是数字；其余仅允许 `A-Za-z0-9_-.:/@+= ` 与空格；
3. 右侧**实时预览**最终会写盘的 `docker-compose.yml` 与 `.env`（预览与真实安装共用同一段服务端渲染逻辑，**所见即所装**）；
4. 点「部署」→ 后台任务执行 `docker compose up -d`，安装日志实时滚动，任务状态由前端每秒轮询；
5. 若 compose 引用了 `1panel-network`，安装前会自动创建该网络。

**卸载**：`docker compose down`（可选带 `-v` 删卷）后删除编排目录下的项目文件夹，双重确认。

> 已安装状态通过「编排目录下是否存在同名项目」判断，因此在「编排」页手工建的同名项目也会显示为「已安装」。

## AI 助手

![AI 助手](https://raw.githubusercontent.com/myyyisbest/wpanel/main/docs/screenshots/ai-light.png)

自行配置任意 **OpenAI 兼容接口**即可启用，例如 DeepSeek、OpenAI、本地 Ollama：

| 字段 | 示例 |
|---|---|
| 接口地址 | `https://api.deepseek.com/v1` |
| 密钥 | `sk-...`（保存后回显为「已保存」，留空表示保持不变） |
| 模型 | `deepseek-chat` |

配置存于 `data/ai.local.json`（不进 git）。接口只返回「是否已配置」，不会回显密钥。

### 三项能力

1. **容器日志诊断** —— 取容器状态（`Status`、`RestartCount`、`StartedAt`）与最近 120 行带时间戳日志，交给模型输出根因与处置步骤（≤300 字）。
2. **Compose 生成** —— 自然语言描述需求，生成 compose v2 语法的 `compose.yaml`，可命名后一键保存到编排目录，随后在「编排」页启动。
3. **运维操作提议** —— 把自然语言翻译成动作列表。模型被约束为**只能**输出 `start` / `stop` / `restart` 三种动作，且 `target` 必须是现有容器名；服务端还会再过一遍白名单校验，最多 10 条。

### 核心约束

> **AI 只有建议权，没有执行权。**

生成的每条动作都会以卡片形式列出，必须逐条点「执行」才真正调用容器接口；没有任何路径能让模型直接触发操作。

## 文件管理

![文件管理](https://raw.githubusercontent.com/myyyisbest/wpanel/main/docs/screenshots/files-light.png)

- **零 agent**：通过 `\\wsl.localhost\<发行版>\...` UNC 共享直读，发行版内不需要跑任何东西。
- **访问身份**：以发行版**默认用户**身份访问，因此 `/root`、`/etc` 等 root 属地天然不可写。
- **根目录白名单**：默认仅 `/home`，可用 `WPANEL_ROOTS=/home,/srv` 扩展（逗号分隔）。
- **能力**：

| 操作 | 限制 |
|---|---|
| 浏览目录 | 单目录最多列出 500 项，目录优先、中文按拼音排序 |
| 在线编辑 | 文本 ≤1MB，二进制自动识别并拒绝 |
| 预览图片 | png / jpg / gif / webp / svg 等 |
| 上传 | ≤100MB，同名可覆盖 |
| 下载 | 流式，无大小限制 |
| 新建文件夹 / 文件 | 同名会报错 |
| 重命名 | 同目录内改名 |
| 删除 | 支持多选，单次最多 100 项，需确认 |

- **安全校验**：路径必须绝对、不含 `..`、不含反斜杠；再对**父目录与目标本身**各做一次 `realpath` 复核，确保真实落点仍在允许根内 —— 针对的是「`/home/dev/current` 是指向 `/etc` 的符号链接」这类跳转。
- **已知限制**：当前平台上经 UNC 共享**无法跟随 Linux 符号链接**，访问链接路径会返回 `ENOENT`。请使用真实路径（如 `/usr/bin` 而非 `/bin`）。详见 [安全模型](安全模型)。

## 日志记录

![日志记录](https://raw.githubusercontent.com/myyyisbest/wpanel/main/docs/screenshots/activity-light.png)

- 记录字段：时间、动作、目标、成功 / 失败、消息（截断 500 字符）。
- 覆盖范围：容器启停删、镜像拉取 / 删除 / 清理、卷操作、Compose 操作、应用商店安装 / 卸载 / 刷新、文件上传 / 保存 / 新建 / 重命名 / 删除、服务启停、WSL 启停、AI 设置保存，以及**所有失败操作**。
- 服务端分页（每页 30 条）+ 关键字搜索（匹配动作 / 目标 / 消息）。
- 存储为 `data/activity.jsonl`，**超过 5MB 自动轮转为 `activity.jsonl.1`**；读取时只回读文件尾部 2MB 窗口，日志再大也不会拖垮内存。
