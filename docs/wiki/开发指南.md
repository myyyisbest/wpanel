# 开发指南

## 技术栈

| 层 | 选型 |
|---|---|
| 前端 | Next.js 16（App Router）+ React 19，构建走 [vinext](https://github.com/vinext)/Vite 8 |
| 控制服务 | 纯 Node（`server.mjs`），**零运行时依赖**，只用 `node:http` / `node:child_process` / `node:fs` |
| 样式 | 单文件 `app/globals.css` + CSS 变量驱动的三态主题，无 UI 框架 |
| 唯一依赖 | `yaml`（解析 1Panel 商店模板与改写 compose 镜像地址） |

## 目录结构

```

│  ├─ ImagesVolumes.tsx    镜像与卷

│  ├─ StorePage.tsx        应用商店

│  ├─ FileManager.tsx      文件管理
│  ├─ ActivityLog.tsx      日志记录
│  ├─ layout.tsx           主题引导脚本（防闪白）
│  └─ globals.css          全部样式
├─ server.mjs              控制服务：全部特权操作
├─ docs/
│  ├─ screenshots/         界面截图（脚本生成）
│  └─ wiki/                Wiki 页面源文件
├─ tools/
│  ├─ screenshot/          截图流水线（模拟 API + Playwright）
│  └─ publish-wiki.ps1     把 docs/wiki/ 推送到 GitHub Wiki
├─ Start-WPanel.ps1 / Stop-WPanel.ps1 / Install-AutoStart.ps1
└─ *.bat                   上述脚本的包装
```

## 本地开发

```bash
npm install

npm run dev         # 前端开发模式（vinext dev，默认 3000）
npm run controller  # 单独启动控制服务（WPANEL_PORT 可覆盖端口）
npm run build       # 生产构建
npm run start       # 生产模式启动前端
npm run lint        # ESLint
npm run typecheck   # tsc --noEmit
```

开发时前端跑在 3000 端口，需要把控制服务的来源白名单放开：

```powershell
$env:WPANEL_UI_ORIGINS = 'http://localhost:3000,http://127.0.0.1:3000'
npm run controller
```

前端要访问控制服务，需在启动 dev server 前注入地址：

```powershell
$env:NEXT_PUBLIC_WPANEL_API = 'http://127.0.0.1:8766'
npm run dev
```

## 提交前检查

CI（`.github/workflows/ci.yml`）在 `push main` 与所有 PR 上执行：

```bash
npm ci
npm run lint
npm run typecheck
npm run build
```

**`npm run build` 走的是 Vite，不做类型检查** —— 所以 `typecheck` 单独跑一遍兜住类型回归。本地提交前请把三条都跑过。

## 截图流水线

`docs/screenshots/` 下的图**不需要真实的 WSL / Docker 环境**即可重新生成：

```bash
node tools/screenshot/mock-api.mjs                            # 模拟控制服务 :8799
NEXT_PUBLIC_WPANEL_API=http://127.0.0.1:8799 npm run dev      # 前端 :8765
node tools/screenshot/capture.mjs                             # 采集浅色 + 深色全套
```

- `mock-api.mjs` 复现 `server.mjs` 的**读接口形状**，返回固定演示数据；任何写操作都只返回一条「演示模式」记录，不会触碰真实环境。
- `capture.mjs` 用 Playwright 打开真实前端，逐个导航项截图。
- 需要新页面 → 在 `capture.mjs` 里加一段 `gotoView` + `shoot`；需要新数据 → 改 `mock-api.mjs` 里的常量。

详见 [`tools/screenshot/README.md`](https://github.com/myyyisbest/wpanel/blob/main/tools/screenshot/README.md)。

## Wiki 维护

Wiki 页面的**源文件在 `docs/wiki/`**，随主仓库一起评审；发布到 GitHub Wiki 用：

```powershell
.\tools\publish-wiki.ps1
```

## 代码约定

- **控制服务不做字符串拼命令**：所有外部命令以数组形式传给 `execFile` / `spawn`；必须进 shell 的场景（如 `cd && docker compose`）用**位置参数**传值，不插入命令文本。
- **新增接口必须过三关**：`X-WPanel-Token` 校验 → 参数正则校验 → 审计日志写入。
- **文件接口新增操作时**，务必走 `checkedUnc()`（内含根目录白名单 + 父目录与目标双重 realpath 校验），不要自己拼 UNC 路径。
- **同步 IO 不进请求热路径**：读接口用 `fs/promises`；必须同步读的小配置文件走 `readJsonCached()`（按 mtime 缓存）。
- **前端不直接接触 shell**：所有动作打到控制服务，前端只负责展示与确认。

## 版本与依赖

- Node ≥ 22.13（`package.json` 的 `engines` 已约束）；
- `vinext` 目前是 `1.0.0-beta`，升级时留意构建产物变化；
- 新增运行时依赖前请三思 —— 控制服务保持零依赖是它能在 WSL 场景下稳定运行的重要原因。
