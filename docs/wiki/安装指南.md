# 安装指南

WPanel 的安装顺序是 **WSL2 → systemd → Docker Engine → Node.js → WPanel**。这不是随意的顺序：WPanel 的每一项能力都建立在「Windows 能访问一个启用了 systemd 的 WSL2 发行版，且发行版里有原生 Docker」之上。地基没打好，面板只会显示「Ubuntu 未运行」。

## 第 0 步：前置检查

以**管理员身份**打开 PowerShell：

```powershell
wsl --version
```

预期看到 `WSL 版本: 2.x.x`。若提示 `Invalid command line option: --version`，说明 WSL 过旧：

```powershell
wsl --update
```

> 系统要求 Windows 11（22H2 及以上）。Windows 10 需要 2004+ 并手动启用虚拟机平台。

## 第 1 步：在 Windows 上装好 WSL2

### 1.1 一键安装（推荐）

```powershell
wsl --install
```

这条命令会依次：启用「适用于 Linux 的 Windows 子系统」与「虚拟机平台」→ 下载 WSL2 内核 → 安装默认 Ubuntu 发行版 → 提示重启。

**重启 Windows** 后 Ubuntu 自动启动，要求设置 **UNIX 用户名**与**密码**。这个账号就是 WPanel 文件管理所使用的身份，请记牢。

### 1.2 指定发行版（可选）

```powershell
wsl --list --online            # 查看可安装的发行版
wsl --install -d Ubuntu-24.04  # 安装指定版本
```

### 1.3 确认 WSL2 与默认发行版

```powershell
wsl --set-default-version 2
wsl --list --verbose
```

确认目标发行版的 `VERSION` 为 `2`，且带 `*`（默认发行版）。

> WPanel 默认连接名为 `Ubuntu` 的发行版。若你的发行版叫 `Ubuntu-24.04` 等，用环境变量 `WPANEL_DISTRO` 指定即可，**不必改名**。

### 1.4 换国内镜像源（可选，强烈建议）

```bash
# 在 Ubuntu 终端内执行（Ubuntu 24.04 为 deb822 格式）
sudo cp /etc/apt/sources.list.d/ubuntu.sources /etc/apt/sources.list.d/ubuntu.sources.bak
sudo sed -i 's|http://archive.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g; s|http://security.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g' /etc/apt/sources.list.d/ubuntu.sources
sudo apt update && sudo apt upgrade -y
```

> Ubuntu 22.04 的源文件是 `/etc/apt/sources.list`，把路径换成它即可。

## 第 2 步：确认发行版启用了 systemd

WPanel 通过 `systemctl` 启停 `docker.service`，**systemd 必须可用**。

- 用 `wsl --install` 安装的**当前版本 Ubuntu，systemd 默认已启用**，通常无需额外配置。
- 其他发行版或较旧镜像仍使用 WSL init，需要手动开启。

### 2.1 检查

```bash
systemctl is-system-running     # running / degraded 即为已启用
```

若报 `System has not been booted with systemd as init system`：

```bash
sudo tee /etc/wsl.conf > /dev/null <<'EOF'
[boot]
systemd=true
EOF
```

然后在 **PowerShell** 中彻底重启：

```powershell
wsl --shutdown
```

重新进入发行版后验证：

```bash
systemctl is-system-running
systemctl list-unit-files --type=service | head
```

> 若发行版缺少 systemd 包：`sudo apt-get update && sudo apt-get install -y systemd systemd-sysv`

## 第 3 步：安装原生 Docker Engine

> 这里装的是 **Docker Engine（docker-ce）**，不是 Docker Desktop。WPanel 需要发行版内由 systemd 托管的原生 `dockerd`。

### 3.1 卸载可能冲突的非官方包

```bash
sudo apt remove $(dpkg --get-selections docker.io docker-compose docker-compose-v2 docker-doc docker-buildx podman-docker containerd runc | cut -f1)
```

提示「没有这些包」属正常。

### 3.2 添加 Docker 官方 apt 仓库

```bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update
```

### 3.3 安装并启动

```bash
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker.service
sudo systemctl status docker --no-pager
```

### 3.4 验证

```bash
sudo docker run --rm hello-world
```

看到 `Hello from Docker!` 即成功。

### 3.5 允许当前用户免 sudo 使用 docker（可选）

WPanel 的操作以 root 身份执行，**不依赖**这一步；只是你手敲命令会更方便：

```bash
sudo usermod -aG docker $USER
```

之后需 `wsl --shutdown` 重进发行版才生效。

## 第 4 步：安装 Node.js（Windows 侧）

```powershell
winget install OpenJS.NodeJS.LTS
```

或从 <https://nodejs.org/> 下载 LTS 安装包。**新开一个** PowerShell 验证：

```powershell
node -v      # v22.13.0 或更高
npm -v
```

启动脚本使用 PowerShell 7：

```powershell
winget install Microsoft.PowerShell
```

## 第 5 步：安装并启动 WPanel

```powershell
git clone https://github.com/myyyisbest/wpanel.git
cd wpanel
npm install
npm run build

.\启动WPanel.bat          # 启动并打开 http://localhost:8765
.\停止WPanel.bat          # 只停面板，不影响 WSL / Docker / 容器
```

### 脚本一览

| 脚本 | 作用 |
|---|---|
| `启动WPanel.bat` | 后台拉起控制服务（8766）与前端（8765），等待就绪后打开浏览器 |
| `停止WPanel.bat` | 只结束 WPanel 自己的进程 |
| `安装开机自启.bat` | 登录后后台静默自启（优先计划任务，无管理员权限时回退到启动文件夹） |
| `卸载开机自启.bat` | 移除上面两种自启方式 |

> 四个 `.bat` 都是 `Start-WPanel.ps1` / `Stop-WPanel.ps1` / `Install-AutoStart.ps1` 的薄包装，需要 `pwsh.exe`（PowerShell 7）。直接调用 `.ps1` 亦可。

## 安装排错

| 现象 | 原因与处理 |
|---|---|
| 页面提示「无法连接 Windows 控制服务」 | 控制服务未启动或端口被占用。运行 `启动WPanel.bat`，查看 `logs/controller.err.log` |
| 总览显示「Ubuntu 未运行」 | 发行版没起来。`wsl -d Ubuntu -- true`，或在面板点「启动 Ubuntu」 |
| 总览显示「systemd 未启用」 | 回到[第 2 步](#第-2-步确认发行版启用了-systemd) |
| Docker 卡片显示「未运行」 | `wsl -d Ubuntu -u root -- systemctl status docker`；必要时 `systemctl enable --now docker.service` |
| 发行版名不是 `Ubuntu` | 设置 `WPANEL_DISTRO`（例如 `set WPANEL_DISTRO=Ubuntu-24.04`）后再启动 |
| 文件管理里 `/home` 打不开或权限不足 | 确认发行版已启动；WPanel 以发行版**默认用户**身份访问文件共享，`/root`、`/etc` 等 root 属地不可操作 |
| 提示「端口 8766 已被占用」 | 关闭占用进程，或设置 `WPANEL_PORT` 换端口（同时需用 `NEXT_PUBLIC_WPANEL_API` 重新构建前端） |
| `启动WPanel.bat` 报找不到 pwsh | `winget install Microsoft.PowerShell` |
| 提示「依赖尚未安装 / 生产版本尚未构建」 | 依次执行 `npm install` 与 `npm run build` |
| `wsl --install` 卡住或报网络错误 | 启用 Windows 功能后重启；或从 Microsoft Store 安装 Ubuntu |
| 关闭面板后容器也停了 | 不会。`停止WPanel.bat` 只杀 WPanel 自己的进程，WSL 与容器不受影响 |
