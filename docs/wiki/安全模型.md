# 安全模型

WPanel 是一个**本机工具**，设计目标是「不把本机 Docker 的 root 权限暴露到网络上」。本页说明它做了什么，以及它的边界在哪里 —— 边界部分同样重要。

## 设计前提

WPanel 的控制服务有能力以 root 身份在 WSL 发行版里执行 `docker` 与 `systemctl` 子命令，并读写发行版文件系统。因此它的安全模型不是「防住能在这台机器上运行代码的人」（那做不到，那人本来就能直接敲 `docker`），而是：

1. **不把能力暴露到网络**；
2. **不让浏览器里打开的任意网页驱动这些能力**（CSRF / DNS rebinding）；
3. **把用户能触达的文件系统范围收窄到明确白名单**；
4. **让所有动作可追溯**。

## 具体措施

### 网络面

- **只监听 `127.0.0.1`**：控制服务不绑定任何外部网卡，局域网与公网都无法直连。
- **来源白名单**：浏览器请求必须带受信任的 `Origin`（默认 `http://localhost:8765` / `http://127.0.0.1:8765`），否则一律 403。可用 `WPANEL_UI_ORIGINS` 调整。
- **Host 校验**：只接受 `127.0.0.1:8766` / `localhost:8766`。这一条针对 **DNS rebinding** —— 攻击者把域名解析到 `127.0.0.1` 时，请求虽来自本机，但 `Host` 头会是攻击者的域名，直接拒绝。
- **安全响应头**：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`。

### 请求鉴权

- **会话令牌**：控制服务每次启动随机生成（24 字节），前端通过 `GET /api/session` 获取，之后所有变更操作与敏感读取都要带 `X-WPanel-Token`。
- **令牌的作用是防 CSRF，不是身份认证**：它让「浏览器里的其他页面」无法构造有效请求。
- **例外**：`/api/session`、`/api/status`、`/api/store/logo/*` 无需令牌 —— 前者要能被前端拿到，中者是只读状态，后者供 `<img>` 直接加载。

### 命令执行面

- **固定白名单命令**：后端**不存在**「传入任意命令字符串并执行」的接口。所有 `wsl.exe` / `docker` / `systemctl` 调用都是代码里写死的子命令，参数经过正则校验（容器名、镜像 ID、卷名、服务 key、项目名、应用 ID 各有独立校验规则）。
- **Compose 不拼字符串**：目录与项目名以**位置参数**传给 `bash`（`bash -lc 'cd -- "$1/$2" && shift 2 && docker compose "$@"'`），而不是插入命令文本，因此项目名中的特殊字符无法造成注入。
- **`WPANEL_COMPOSE_DIR` 有格式约束**：必须是不含空格与引号的绝对路径。

### 文件访问面

三重防线：

1. **根目录白名单**：`WPANEL_ROOTS`（默认 `/home`），路径必须落在其中；
2. **路径标准化**：必须绝对、拒绝 `..` 段、拒绝反斜杠与 NUL、长度 ≤2048；
3. **双重 realpath 校验**：对**父目录**与**目标本身**分别求真实路径，都必须在允许根内。

第 3 条是防符号链接逃逸的关键。举例：`/home/dev/current` 是指向 `/etc` 的符号链接，

- 只校验目标时，`/home/dev/current/passwd` 看起来在 `/home` 下；
- 加上父目录 realpath 校验后，`/home/dev/current` 的真实路径是 `/etc`，不在允许根内 → 直接拒绝。

覆盖删除 / 改名 / 新建 / 上传 / 读取 / 编辑全部文件操作。

### 危险操作

需要前端二次确认，并全部写入审计日志：

- 删除镜像 / 卷、清理未使用镜像 / 卷 / 已停止容器；
- 关闭 WSL（需 `confirm: "SHUTDOWN"`）、停止 Docker（需 `confirm: "STOP_DOCKER"`）；
- 卸载应用、删除 Compose 项目（含文件夹，双重确认）；
- 文件删除（多选时一次最多 100 项）。

### 凭据

- AI 密钥存于 `data/ai.local.json`，明文、本机、不进 git；
- `GET /api/ai/settings` 只返回 `baseUrl`、`model` 与 `hasKey`，**不回显密钥**；
- 界面留空保存时发送 `__KEEP__` 占位符，服务端识别后沿用旧密钥，不会把占位符覆盖上去。

### 审计

- 所有操作（含失败）写入 `data/activity.jsonl`；
- 单条消息截断 500 字符；
- 文件超过 5MB 自动轮转，读取只回读尾部 2MB 窗口。

## 已知边界

以下不是漏洞，是设计取舍。**请务必知悉**：

| 边界 | 说明 |
|---|---|
| **本地进程不受令牌约束** | 令牌只防跨站请求伪造。能在这台机器上运行代码的程序，本来就可以直接调用 `docker`。WPanel 没有引入新风险，但**绝对不要把 8765 / 8766 端口转发或反向代理到公网**。 |
| **容器命令盒可执行任意命令** | 「命令盒」会在目标容器内以容器默认用户执行单条命令，能力上等价于进入容器终端。它受令牌保护且仅本机可达，但请只在可信环境使用。若你的使用场景不需要它，可以忽略该功能。 |
| **商店模板来自第三方** | 默认模板源是 1Panel 官方仓库。WPanel 会忽略模板中的脚本类字段，但 `docker-compose.yml` 内容本身来自上游。安装前建议先看「预览」，或换成自建模板源。 |
| **镜像加速站可见你的拉取行为** | 默认 `docker.1ms.run` 会看到你拉取的镜像名。介意的话在「商店设置」里把加速站留空，改为直连 `docker.io`。 |
| **AI 会把日志发给第三方** | 「容器日志诊断」会把容器状态与最近 120 行日志发送到你配置的接口。使用第三方 API 前请确认日志中不含敏感信息。 |
| **无多用户与权限体系** | WPanel 是单用户本机工具，没有账号、角色、权限分级。 |
| **SSE 令牌走查询串** | 浏览器 `EventSource` 无法携带自定义请求头，因此实时日志接口的令牌放在查询参数里（`?token=`）。已通过 `Referrer-Policy: no-referrer` 降低泄露面，但它仍可能出现在你自己的调试记录中。 |
| **未做请求限流** | 本机工具，未实现速率限制。 |

## 自查清单

部署完成后建议确认：

- [ ] `netstat -ano | findstr 8766` 只显示 `127.0.0.1:8766`，**没有** `0.0.0.0:8766`
- [ ] 没有为 8765 / 8766 配置任何端口转发、反向代理或内网穿透
- [ ] `data/` 目录不在版本控制中（`git check-ignore data/ai.local.json` 有输出）
- [ ] 若扩展了 `WPANEL_ROOTS`，确认新根目录下没有指向敏感位置的符号链接
- [ ] 若配置了 `services`，确认它们在「安全关闭 WSL」时被停掉是符合预期的
