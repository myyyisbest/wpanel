# 常见问题

## 启动与连接

### 页面提示「无法连接 Windows 控制服务，请运行"启动WPanel.bat"」

按顺序排查：

1. **控制服务是否在跑**：`netstat -ano | findstr 8766` 应看到 `127.0.0.1:8766` 处于 `LISTENING`；
2. **看日志**：`logs/controller.err.log`，常见的是端口被占用或 `node_modules` 缺失；
3. **端口被占用**：日志里会打印「端口 8766 已被占用」。关闭占用进程，或设 `WPANEL_PORT` 换端口；
4. **前端指向错了**：`NEXT_PUBLIC_WPANEL_API` 是**构建时**注入的。改完必须 `npm run build` 重新构建，只重启不重建无效。

### 改了 UI 端口后所有请求都 403

`WPANEL_UI_ORIGINS` 默认只放行 8765。改前端端口时同步设置：

```powershell
$env:WPANEL_UI_ORIGINS = 'http://localhost:9000,http://127.0.0.1:9000'
```

改 `WPANEL_PORT` 时同理要更新 `WPANEL_ALLOWED_HOSTS`。

### 提示「Host 不受信任」

说明请求的 `Host` 头不在白名单里。正常访问应该是 `localhost:8766` 或 `127.0.0.1:8766`。

- 如果你通过反向代理 / 端口转发访问 → **不要这么做**，见[安全模型](安全模型)；
- 如果你改了 `WPANEL_PORT` → 同步更新 `WPANEL_ALLOWED_HOSTS`。

### `启动WPanel.bat` 一闪而过 / 报找不到 PowerShell

四个 `.bat` 会优先使用 PowerShell 7（`pwsh.exe`），找不到时**自动回退到 Windows 自带的 `powershell.exe`（5.1）**，因此通常无需安装任何东西。

若两者都报找不到，说明系统 PATH 被裁剪过 —— `powershell.exe` 位于 `%SystemRoot%\System32\WindowsPowerShell\v1.0\`，把它加回 PATH 即可。

若想使用 PowerShell 7：

```powershell
winget install Microsoft.PowerShell
```

装完新开一个窗口再试。

### 提示「依赖尚未安装」或「生产版本尚未构建」

```powershell
npm install
npm run build
```

### 提示「端口 8766 已被占用」

先运行 `停止WPanel.bat`；仍占用则找出占用进程：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8766 | Select-Object OwningProcess
```

或直接换端口（记得同步 `WPANEL_ALLOWED_HOSTS` 与 `NEXT_PUBLIC_WPANEL_API`）。

## WSL 与 Docker

### 总览显示「Ubuntu 未运行」

发行版没启动。手动拉起：

```powershell
wsl -d Ubuntu -- true
```

或在面板「总览」页点「启动 Ubuntu」。若提示发行版不存在，用 `wsl -l -v` 确认名字，再用 `WPANEL_DISTRO` 指定。

### 总览显示「systemd 未启用」

见[安装指南 · 第 2 步](安装指南#第-2-步确认发行版启用了-systemd)。要点：`/etc/wsl.conf` 加 `[boot] systemd=true`，然后 `wsl --shutdown`。

### Docker 卡片显示「未运行」

```powershell
wsl -d Ubuntu -u root -- systemctl status docker --no-pager
wsl -d Ubuntu -u root -- systemctl enable --now docker.service
```

若报找不到 `docker.service`，说明装的是 `docker.io`（发行版自带包）或 Docker Desktop 而非官方 `docker-ce`。参考[安装指南 · 第 3 步](安装指南#第-3-步安装原生-docker-engine)重装。

### 我用的就是 Docker Desktop，能用吗？

**不能。** WPanel 需要发行版内由 systemd 托管的原生 `dockerd`（`docker.service`），Docker Desktop 的 daemon 跑在它自己的虚拟机里，`systemctl` 看不到也管不到。若你只是想用 Docker Desktop，请继续用 Docker Desktop 自带的面板。

### 关闭面板后容器会不会被停掉？

不会。`停止WPanel.bat` 只结束 WPanel 自己的两个进程（8765 / 8766），不碰 WSL、Docker 和容器。真正会停容器的是「总览」页的**安全关闭 WSL**，而且那需要你确认。

### 「安全关闭 WSL」会停哪些服务？

按顺序：

1. `docker stop -t 60` 停掉全部运行中的容器；
2. 停掉 `docker.service` / `docker.socket` / `containerd.service`；
3. 停掉你在 `data/wpanel.local.json` 的 `services` 里配置的服务；
4. 停掉 `WPANEL_STOP_UNITS` 里列出的单元；
5. `wsl --terminate <发行版>`。

如果你有服务**不希望**被一起停掉，就不要把它写进 `services`。

## 文件管理

### `/home` 打不开，或者提示「权限不足」

- 确认发行版正在运行（文件共享依赖运行中的发行版）；
- WPanel 以发行版**默认用户**身份访问 UNC 共享，`/root`、`/etc`、`/var/lib/docker` 等 root 属地会报权限不足 —— 这是设计如此；
- 若目录属于 root，在发行版内 `sudo chown -R $USER:$USER <目录>`。

### 想管理 `/home` 以外的目录

```powershell
$env:WPANEL_ROOTS = '/home,/srv,/opt/data'
```

重启控制服务生效。**注意**：扩大范围会同时扩大攻击面，且新根目录下不宜有指向敏感位置的符号链接 —— 虽然当前平台本就无法跟随链接，但换平台或换挂载方式后语义可能变化。

### 提示「路径超出允许范围（默认仅开放 /home，可用 WPANEL_ROOTS 扩展）」

两种可能：

1. 路径确实不在 `WPANEL_ROOTS` 里；
2. 路径（或其父目录）是**指向白名单之外的符号链接**，被 `realpath` 复核拦下。

### 点进某个目录提示找不到（ENOENT），但目录明明存在

多半是该目录为 Linux 符号链接。Windows 侧经 UNC 共享访问 WSL 时**无法跟随符号链接**，`/bin`、`/lib`、`/etc/os-release` 这类链接一律返回 `ENOENT`，而同一目标的真实路径（如 `/usr/bin`）访问正常。

这是平台限制，不是配置问题 —— 请直接使用真实路径。详见 [安全模型](安全模型) 中的实测表格。

### 上传/编辑大小限制

- 在线编辑：单文件 ≤1MB 文本，二进制会被识别并拒绝（改用下载）；
- 上传：≤100MB；
- 镜像导入：≤2GB。

## 应用商店

### 商店列表一直转圈 / 提示「模板源下载失败」

模板源走 `codeload.github.com` 的 tarball（git 协议在部分网络下不可达）。排查：

1. 浏览器能否打开 `https://codeload.github.com/1Panel-dev/appstore/tar.gz/refs/heads/main`；
2. 若不能，在「商店设置」里换成可访问的镜像仓库或自建源；
3. 缓存坏了就点「更新源」强制重新下载（会清空 `data/store-cache/`）。

### 安装卡在拉镜像 / 提示「部署失败」

镜像拉取慢是主因。在「商店设置」里配置可用的**镜像加速站**（默认 `docker.1ms.run`）。安装日志会实时滚动，失败原因通常在最后几行。

### 「编排目录中已存在同名项目」

卸载或改名后再装。注意「已安装」状态就是靠「编排目录下是否有同名项目」判断的，所以在「编排」页手工建的同名项目也会挡住安装。

### 卸载会不会删我的数据？

默认**不会**。`docker compose down` 不带 `-v`，数据卷保留。只有显式勾选「同时删除卷」才会 `down -v`。但**项目文件夹（含 compose 与 .env）一定会被删除**。

## AI 助手

### 提示「尚未配置 AI」

在「AI 助手」页填写接口地址、密钥、模型三项并保存。地址需为 OpenAI 兼容的 `/v1` 根路径，例如 `https://api.deepseek.com/v1`。

### 提示「无法连接 AI 接口」

地址写错、网络不通，或服务需要代理。先在 Windows 上用 `curl` 验证该地址可达。

### 二次保存设置后 AI 就不能用了

已修复。界面在密钥留空时会发送 `__KEEP__` 占位符，服务端识别后沿用旧密钥。若你用的是旧版本，重新填一次密钥即可。

### AI 会不会自己把容器停了？

不会。模型只能输出 `start` / `stop` / `restart` 三种动作建议，每条都要你点「执行」；服务端还会再过一遍白名单校验。**AI 没有执行权。**

## 开发与贡献

### `npm run build` 报类型错误但构建过了

`npm run build` 走 Vite（vinext），**不做类型检查**。CI 里单独跑 `npm run typecheck`（`tsc --noEmit`）兜住类型回归。提交前请本地跑一遍：

```bash
npm run lint && npm run typecheck && npm run build
```

### 能删掉 `next.config.ts` 吗？

**不能。** 文件内容为空，但 vinext 会主动查找并读取 `next.config.*`，删掉可能导致配置探测失败。真正的构建配置在 `vite.config.ts`。
